# Личный бюджет

Небольшое веб-приложение для учёта личных доходов и расходов. Основной экран —
календарь на месяц, где каждый день показан квадратной плиткой с тремя числами:
приход за день, расход за день и накопленный итог на конец этого дня.

Ни сборки, ни зависимостей: чистые HTML, CSS и JavaScript. По умолчанию все данные
лежат в браузере и никуда не отправляются; по желанию их можно синхронизировать
между устройствами через свой сервер (см. раздел «Синхронизация между устройствами»).

## Запуск

Откройте `index.html` двойным кликом — этого достаточно.

Если браузер ограничивает работу с локальными файлами, запустите локальный сервер:

```bash
python -m http.server 8777
```

и откройте <http://127.0.0.1:8777/>.

Приложение также опубликовано: **<https://srglab.github.io/CashBalance/>**.

### Как это развёрнуто

Сайт собирается из тех же файлов, что лежат в репозитории, — сборки нет: workflow
копирует на сайт четыре файла приложения (`index.html`, `styles.css`, `app.js`,
`sync.js`) и публикует их как есть. Каждый пуш в `main` сам запускает workflow
`.github/workflows/pages.yml` и обновляет сайт; ждать ручной сборки не нужно, обычно
деплой занимает около минуты. Повторить публикацию вручную можно во вкладке
**Actions** → **Deploy to GitHub Pages** → **Run workflow**.

**Данные не переезжают вместе с сайтом.** `localStorage` привязан к адресу: у
локального открытия, у <http://127.0.0.1:8777/> и у опубликованного сайта это три
независимых хранилища. Чтобы перенести учёт, откройте старый адрес, нажмите
**Экспорт**, затем на новом — **Импорт**.

Сайт и репозиторий публичные, но это безопасно: в коде нет ни одной цифры вашего
бюджета — учёт целиком остаётся в вашем браузере и никуда не отправляется.

## Как пользоваться

### Календарь

Вверху — название месяца, итоги за него (приход, расход, баланс) и стрелки для
перехода между месяцами. Кнопка **Сегодня** возвращает к текущему месяцу.

Каждая плитка дня показывает три числа:

| Число | Значение |
| --- | --- |
| зелёное `+` | приход за этот день |
| красное `−` | расход за этот день |
| жирное | накопленный итог на конец этого дня |
Накопленный итог — это все движения денег с самого начала учёта и до конца
указанного дня, то есть баланс «на руках» после этого дня. Он нужен, чтобы сразу
видеть, сколько останется, например, к концу месяца. Если движений ещё не было,
он совпадает с балансом месяца, а точное значение всегда есть в подсказке
(наведение на плитку) и в панели дня.

Значок `↻` означает, что в этом дне есть повторяющаяся операция. Крупные суммы
сокращаются: `1 250`, `12,5 к`, `90 к`.

### Панель дня

Нажмите на любую плитку — откроется панель выбранного дня: список его операций и
форма добавления. Форма работает с датой выбранного дня, поэтому отдельного поля
«дата» нет.

Панель можно не закрывать: нажимайте на другие плитки — она сразу переключается
на новый день. На широком экране она сдвигает календарь влево, на узком —
открывается поверх с затемнением. **Esc** или нажатие на затемнение закрывает
панель.

В шапке панели видно четыре числа: приход за день, расход за день, баланс за день
и накопленный итог.

### Назначение и словарь

Поле «Назначение» (бывшая «Заметка») — это то, ради чего тратились деньги: «Кофе
навынос», «Аренда за сентябрь», «Перевод маме». Приложение собирает из этих
значений словарь и подставляет варианты, пока вы печатаете:

- список открывается сам при нажатии на поле и обновляется на каждый символ;
- поиск не учитывает регистр и ищет по любой части названия;
- сверху идут назначения того же типа операции (расход или доход), дальше — самые
  частые; у каждого показан счётчик использований, например `12 раз`;
- стрелки `↑` и `↓` перебирают варианты, `Enter` подставляет выделенный, мышь
  работает обычным нажатием, `Esc` закрывает список (панель дня при этом
  остаётся открытой);
- без выделения `Enter` отправляет форму как обычно.

Словарь не хранится отдельно: он каждый раз собирается из заметок всех операций,
поэтому новые назначения появляются в подсказках сразу после сохранения, а
переименование или удаление операции автоматически отражается в списке. Отдельного
хранилища для него не нужно.

Под полем показано, сколько сейчас значений в словаре.

### Повторения

В форме есть поле «Повторение»:

| Вариант | Пример |
| --- | --- |
| Не повторять | разовая покупка |
| Каждый день | кофе, 300 ₽ в день |
| Каждую неделю | абонемент; можно выбрать несколько дней недели |
| Каждый месяц | аренда 1-го числа |

Дополнительно доступны «повторять каждые N дней/недель/месяцев» и «повторять до»
с ограничением по дате. Для еженедельного повторения выбираются конкретные дни
недели — например, по понедельникам и четвергам.

Повторения не создают отдельных записей: хранится одна операция с правилом, а
календарь сам разворачивает её на нужные дни. Поэтому файл экспорта не растёт.

Если операция с 31-го числа повторяется каждый месяц, в месяцах с 30 днями или
меньше она пропускается (дата не переносится на конец месяца).

### Правка и удаление

У каждой операции в списке дня есть кнопки правки и удаления. Правка повторяющейся
операции меняет все её повторения — в форме об этом есть напоминание. Удаление
спрашивает подтверждение и тоже удаляет всю серию. Удалить только один день из
серии нельзя.

## Хранение данных

Все операции сохраняются в `localStorage` браузера под ключом `pb.transactions.v2`
и загружаются при следующем открытии. Пока синхронизация выключена, данные никуда
не отправляются. Очистка данных браузера удалит и учёт — поэтому пользуйтесь
экспортом, а с несколькими устройствами ещё и синхронизацией.

Кнопка **Экспорт** сохраняет копию в файл `budget-ГГГГ-ММ-ДД.json` — для резервной
копии или переноса на другой компьютер. **Импорт** читает такой файл. Кнопка
**Очистить всё** удаляет все операции.

### Почему в приложении напоминание о копии

Данные лежат в `localStorage` — это кэш браузера, а не надёжное хранилище. Его
можно потерять при очистке истории, переустановке браузера или переезде на другой
компьютер. Синхронизация чинит вторую половину этой проблемы, но не первую:
сбросили базу Worker — потеряли всё. Поэтому копия остаётся нужной:

- пока копия не выгружена, сверху висит плашка «стоит выгрузить резервную копию»;
- после первой выгрузки плашка пропадает и появляется снова, только если копии
  нет больше 30 дней;
- при пустом учёте напоминание не показывается.

Копия — обычный JSON, её достаточно держать в любом облаке. Обратную совместимость
обеспечивает **Импорт**.

### Про переход на базу данных

`localStorage` хватает для хранения: лимит около 5 МБ, это десятки тысяч записей,
тогда как у личного бюджета их сотни.

Но у него есть две вещи, которых он не умеет: **общий доступ с телефона и
компьютера сразу** и **страховку от потери данных**. Первое решает серверная
база, второе — выгрузка копии. Поэтому база появилась, но как необязательная
надстройка, а не как условие работы приложения.

## Синхронизация между устройствами

Синхронизация **выключена по умолчанию**. Без неё приложение ведёт себя ровно
как раньше: работает офлайн и по двойному клику, ничего не отправляет.

Включается кнопкой **Синхронизация** в шапке: нужно указать адрес Worker и пароль.
После этого операции появляются на всех устройствах, где задан тот же адрес и
пароль.

Что стоит знать:

- **Данные покидают устройство.** Они ложатся в вашу базу Cloudflare D1. Для
  этого пароль обязателен: без него любой, кто знает адрес Worker, прочитал бы
  бюджет. Сайт при этом публичный, пароль в него не входит — он хранится как
  секрет Worker.
- **localStorage остаётся основным хранилищем.** Приложение всегда пишет учёт
  на устройство и только затем отправляет серверу. Если сеть пропала, ничего не
  теряется: обмен повторится позже сам.
- **Пароль не хранится.** В браузере лежит только подпись сессии, и она
  перестаёт действовать через 30 дней — тогда приложение попросит пароль снова.

### Что происходит при двух устройствах

У каждой операции есть счётчик изменений `rev`. Он растёт при каждой правке, и
побеждает версия с бо́льшим `rev`. Сравниваются счётчики, а не время: часы на
разных устройствах расходятся, счётчик — нет.

- Правка на телефоне приезжает на компьютер при следующем обмене (раз в минуту
  либо при возврате на экран).
- Если обе правки случились одновременно, останется та, что пришла на сервер
  позже, — вторая получит первую при следующем обмене. Разбирать такие случаи
  вручную не нужно, но они возможны.
- Удаление помечает операцию как удалённую, а не стирает её, поэтому она не
  «воскреснет» на других устройствах. Удалённую запись можно восстановить,
  вернувшись из резервной копии.
- «Удалить всё» и импорт файла тоже сообщаются серверу — иначе он вернул бы
  прежние операции обратно.

### Настройка своего сервера

Нужен бесплатный аккаунт Cloudflare.

```bash
npm install -g wrangler
wrangler login

# 1. база; в выводе будет database_id — его вписать в wrangler.toml
wrangler d1 create cashbalance

# 2. таблицы
wrangler d1 execute cashbalance --file=worker/schema.sql --remote

# 3. секреты: их нельзя положить в репозиторий, поэтому только так
wrangler secret put BUDGET_PASSWORD
wrangler secret put SESSION_SECRET

# 4. запуск
wrangler deploy
```

`wrangler deploy` напечатает адрес вида `https://cashbalance-sync.workers.dev` —
его и вводите в приложении.

`SESSION_SECRET` — произвольная длинная строка, её смысл только в том, чтобы
подделать чужую сессию было невозможно. Сменить секрет можно в любой момент:
`wrangler secret put SESSION_SECRET` (действующие сессии после этого отвалятся,
приложение попросит пароль заново).

## Формат записи

```json
{
  "id": "…",
  "type": "expense",
  "amount": 45000,
  "category": "Жильё и коммуналка",
  "note": "аренда за сентябрь",
  "start": "2026-09-01",
  "repeat": "monthly",
  "repeatEvery": 1,
  "weekdays": [],
  "end": null,
  "rev": 1
}
```
| Поле | Значение |
| --- | --- |
| `type` | `expense` (расход) или `income` (доход) |
| `amount` | сумма в рублях, число |
| `category` | категория из списка для выбранного типа |
| `note` | назначение — произвольный текст, из него собирается словарь подсказок |
| `start` | дата начала в формате `ГГГГ-ММ-ДД` |
| `repeat` | `none`, `daily`, `weekly` или `monthly` |
| `repeatEvery` | период повтора: 1 — каждый, 2 — через один и т. д. |
| `weekdays` | дни недели для еженедельного повтора, от 1 (пн) до 7 (вс) |
| `end` | дата окончания или `null`, если повтор бессрочный |
| `rev` | счётчик правок для синхронизации; в старых файлах его нет и считается равным 1 |

Файлы из первой версии приложения (с полем `date` вместо `start`) читаются
корректно: такие записи автоматически трактуются как неповторяющиеся.

Экспорт отдаёт только живые операции. Служебные ключи синхронизации (токен,
курсор, надгробия удалений) в файл не попадают — на новом устройстве они и не
нужны, там всё равно запрашивается сервер.

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | разметка страницы |
| `styles.css` | стили, адаптивная вёрстка, тёмная тема |
| `app.js` | логика: календарь, повторения, накопленный итог, словарь назначений, хранение |
| `sync.js` | обмен с сервером; при отсутствии сервера ничего не делает |
| `worker/src/index.js` | Worker: пароль, вход, приём и раздача операций |
| `worker/schema.sql` | таблицы D1: операции и журнал изменений |
| `wrangler.toml` | конфигурация Worker и привязка базы |
| `.github/workflows/pages.yml` | автопубликация на GitHub Pages при каждом пуше |

На сайт публикуются только `index.html`, `styles.css`, `app.js` и `sync.js`:
workflow копирует их поимённо. Поэтому исходники Worker и резервные копии
бюджета в публичном репозитории не оказываются.
